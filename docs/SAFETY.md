# 运行安全：实际保护与边界

## 本次落实的保护

- 旧高风险测试和非PPO baseline半成品均已移入legacy，不在活动测试路径。
- 主线程执行 `tools/lab.py` 作为可信supervisor。负载在Bubblewrap新文件系统中，只看到必要系统目录、固定只读源码和显式只读依赖；不把整个宿主根目录挂入。
- 唯一普通数据写入点是自己的 `/output` 和 `/tmp`。父进程的manifest/status/log不映射给子程序写入；源码、PDF和恢复归档原件不作为可写目录。
- 子进程独立PID、无网络、无宿主会话环境变量；超时终止，后台子进程在正常结束和超时场景均有构造测试。
- 运行器没有delete/clean命令。每个run目录独占新建；测试只清理自己由TemporaryDirectory创建的随机夹具，不使用stdout当清理目标。
- 沙箱缺失或启动失败就失败，不退回裸执行。`--`会明确从参数中剥离，空命令和非法标签在启动前拒绝。
- `tools/src/tests/configs`下的普通文件（含文本资源、二进制小夹具与可执行位）进入源码快照；隐藏/缓存/私人目录排除，符号链接和超过64MiB/2000文件的源码范围明确拒绝，不静默丢失。显式输入也不得引用隐藏或私人路径。

## 不是这些保证

- 这是降低误操作影响的隔离，不是对恶意代码、内核漏洞或GPU驱动的完整安全证明。
- 主线程和builder的文件编辑权限仍由Codex宿主沙箱控制；launcher不会自动拦截所有人直接发出的任意shell命令。因此AGENTS禁止直接执行项目负载、递归清理和无审核旧代码。角色配置本身不等于操作系统权限隔离。
- `--disk-mib`监测artifacts、scratch和日志，存在轮询超量窗口；RLIMIT_FSIZE只限制单文件，不是硬总磁盘配额。RLIMIT_AS是每进程虚拟地址空间上限，不是全进程树总RSS配额；私有/dev/shm使用内存。嵌套运行不得提高继承的硬上限，manifest记录请求值与实际生效上限。
- 额外 `--runtime` 必须是专门的依赖目录，作为只读映射；不把私人目录、宿主根或项目根当runtime。`--gpu`只显式映射可见NVIDIA设备；没有设备时失败，不默默降到CPU。GPU可用性需在目标解释器与实际沙箱中单独验证。
- runtime拒绝当前项目根及其祖先，但依赖目录是实时只读挂载，仍可能被宿主修改；开展科学运行时必须固定环境并在任务/配置中记录实际版本，运行期间不修改依赖。
- 终端中断会记录失败；SIGTERM/SIGKILL或宿主崩溃可能留下`running`记录。`status`将其标记为未核验，不能凭旧PID或状态文件断言仍在运行；重新启动仍受单任务锁约束，不手动删除锁。Bubblewrap的父进程死亡保护不等于完成了状态记录。
- legacy本地归档与原项目同盘。它保护逻辑恢复材料，不抵御磁盘损坏；真正独立的备份仍待建立。重要训练前应确定第二份持久副本策略。

## 实验与测试

测试必须通过外层launcher运行，避免测试本身的cleanup再次接触真实工作区。构造测试覆盖正常写产物、源码写/删/改名拒绝、绝对路径/符号链接越界、空stdout及`.`、失败/超时、后台子进程、缺失/拒绝沙箱、输入快照和检索隐私。

只读诊断（读文件、解析语法/JSON、PDF信息、版本查询）可直接执行；它们不等于允许导入未知旧模块或启动模拟器。发现新风险先保留原件，再修最小缺陷；不要以安全为名堆出几十项人工审批。
